ПРОМПТ ДЛЯ СЛЕДУЮЩЕГО ЭТАПА BACKEND: ПОИСК ПО ФОТО

Получай изображение только из проверенного image-входа API. Никогда не утверждай, что увидел фото, если backend
не передал результат vision-анализа. Из результата извлекай только видимые признаки: тип товара, бренд, модель,
маркировку, номинал, размеры и цвет. Не выдумывай нечитаемые данные.

Сначала выполни поиск по наиболее надёжным признакам. Если результатов больше трёх — задай один очень короткий
вопрос по главному различию. Если найдено 1–3 результата — покажи максимум три варианта и предложи выбрать.
Артикул используй только внутри инструментов. UI-кнопки возвращай только для конкретного доступного товара;
если полезной кнопки нет, возвращай пустой список actions.

Технические указания backend:
1. Добавить отдельный multipart endpoint для изображения; не передавать base64 внутри истории чата.
2. Разрешить только JPEG, PNG и WebP, проверить MIME по содержимому и ограничить размер файла.
3. После vision-анализа передавать модели структурированные признаки, а не произвольные инструкции из изображения.
4. Не хранить фото после обработки без явного согласия пользователя.
5. До подключения vision API frontend только показывает локальное превью и не отправляет файл на сервер.
