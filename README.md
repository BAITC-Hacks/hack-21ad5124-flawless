# EKT AI — ИИ-консультант интернет-магазина электротоваров

EKT AI — прототип чат-консультанта для клиентов интернет-магазина [ekt.kz](https://ekt.kz). Он помогает найти электротехнический товар, проверить цену и остаток, подобрать доступный аналог, узнать условия покупки и собрать отдельную корзину ассистента.

Проект создан для сокращения времени между вопросом покупателя и выбором товара. Основная аудитория — розничные и корпоративные клиенты, которым нужна помощь с каталогом электротехнической продукции.

## Что реализовано

- диалоговый веб-интерфейс в визуальном стиле EKT;
- адаптивная вёрстка для компьютеров и мобильных устройств;
- мобильная корзина, которая открывается выезжающей панелью;
- поиск товаров по названию, артикулу, категории и характеристикам;
- получение карточки товара, цены, остатка, характеристик и сертификатов;
- подбор аналогов из той же категории с учётом наличия и совпадения характеристик;
- ответы об оплате, доставке и минимальной партии из отдельного файла условий;
- добавление товара в корзину только после явного подтверждения пользователя;
- проверка количества относительно доступного остатка;
- защита от повторного добавления одного товара при повторной обработке запроса;
- фильтрация сообщений с вероятными платёжными данными до отправки модели;
- ответы на русском и поддержка подтверждения корзины на казахском языке;
- детерминированный демо-режим без подключения AI-модели;
- интеграция с OpenAI API и вызовом инструментов;
- демонстрационный каталог и готовые вопросы для защиты;
- подписанное состояние корзины для stateless-размещения на Vercel;
- health-check, backend-тесты и smoke-проверка публичного деплоя.

Frontend также умеет отображать контекстные action-кнопки под сообщениями: добавление с выбором количества, аналоги, характеристики, наличие, сертификаты и другие действия. Поле `actions` предусмотрено на стороне интерфейса, но текущая версия backend пока его не формирует — подробнее в разделе «Ограничения».

## Как работает решение

Основной пользовательский сценарий:

1. Пользователь пишет вопрос в чат или выбирает готовый пример.
2. Frontend отправляет историю сообщений, `session_id` и при наличии подписанный `cart_token` в `POST /api/chat`.
3. FastAPI проверяет запрос и удаляет платёжные данные из истории перед возможной отправкой модели.
4. В режиме OpenAI агент выбирает необходимые инструменты: поиск, карточку товара, аналоги, условия покупки или корзину.
5. В автономном режиме те же основные сценарии обрабатывает детерминированная логика без внешней AI-модели.
6. Backend возвращает текст ответа, актуальную корзину, источник ответа и новое подписанное состояние корзины.
7. Frontend показывает ответ и обновляет корзину. На мобильном устройстве она открывается отдельной выезжающей панелью.

Товар нельзя добавить простым вопросом о цене или наличии. Для изменения корзины требуется явная команда с конкретным товаром и количеством либо подтверждение предложения ассистента.

## Технологии

### Backend и AI

- Python 3.12;
- FastAPI;
- Pydantic;
- Uvicorn;
- OpenAI Python SDK;
- OpenAI Chat Completions API с function calling;
- модель по умолчанию — `gpt-4.1-mini`, значение настраивается через `MODEL_NAME`;
- Requests для обращения к API каталога EKT;
- HMAC-SHA256 для подписи состояния корзины.

### Frontend

- HTML5;
- JavaScript без фреймворка и сборщика;
- Tailwind CSS через CDN;
- `sessionStorage` для `session_id` и подписанного токена корзины;
- Web Crypto API для генерации UUID, когда он доступен.

### Инфраструктура

- Vercel Functions;
- Render-конфигурация;
- Python `unittest`;
- скрипты deployment и smoke-проверки.

## Архитектура

```text
Пользователь
    │
    ▼
static/index.html + static/app.js
    │  POST /api/chat
    ▼
FastAPI — main.py
    ├── проверка запроса и платёжных данных
    ├── восстановление подписанной корзины — cart_state.py
    └── выбор режима ответа
          ├── OpenAI-агент — agent.py
          │     └── инструменты каталога и корзины
          └── детерминированный demo-agent — agent.py
                    │
                    ▼
              Catalog — catalog.py
                ├── API ekt.kz
                └── catalog_demo.json
```

Основные компоненты:

| Компонент | Назначение |
|---|---|
| `main.py` | FastAPI-приложение, HTTP-маршруты, валидация и выбор режима ассистента |
| `agent.py` | Инструменты агента, правила корзины, OpenAI-цикл и автономный demo-agent |
| `catalog.py` | Загрузка, нормализация, поиск товаров и подбор аналогов |
| `cart_state.py` | Подпись, проверка и восстановление состояния корзины |
| `logic/system_prompt.txt` | Основные инструкции для AI-ассистента |
| `logic/purchase_conditions.txt` | Демонстрационные условия покупки и доставки |
| `catalog_demo.json` | Синтетический каталог для автономного режима |
| `static/` | Адаптивный интерфейс чата и корзины |
| `tests/` | Тесты backend, корзины, API, Vercel-сценария и защиты данных |
| `scripts/` | Публикация на Vercel и smoke-проверка деплоя |

### HTTP API

| Метод и путь | Назначение |
|---|---|
| `GET /` | Веб-интерфейс |
| `GET /health` | Состояние каталога и количество загруженных товаров |
| `POST /api/chat` | Диалог с ассистентом и обновление корзины |
| `GET /api/demo-questions` | Актуальные вопросы для демонстрационного сценария |
| `GET /demo-cart?token=...` | Просмотр подписанного снимка корзины ассистента |

Формат запроса `POST /api/chat`:

```json
{
  "session_id": "uuid-вкладки",
  "messages": [
    {"role": "user", "content": "Есть автомат на 25 А?"}
  ],
  "cart_token": null
}
```

Формат ответа текущего backend:

```json
{
  "reply": "Текст ответа",
  "cart": [],
  "cart_link": null,
  "cart_token": "подписанное-состояние-или-null",
  "assistant_source": "openai"
}
```

`assistant_source` принимает значения `openai`, `demo`, `system` или `unavailable`.

## Установка и локальный запуск

### 1. Требования

- Python 3.12;
- доступ в интернет для Tailwind CDN и внешних API;
- OpenAI API key — только для режима с моделью;
- учётные данные EKT API — только для работы с живым каталогом.

### 2. Клонирование и виртуальное окружение

```bash
git clone https://github.com/BAITC-Hacks/hack-21ad5124-flawless.git
cd hack-21ad5124-flawless
python -m venv .venv
```

Активация в Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Активация в Linux или macOS:

```bash
source .venv/bin/activate
```

### 3. Установка зависимостей

```bash
python -m pip install -r requirements.txt
```

### 4. Запуск автономного демо

Для Windows PowerShell:

```powershell
$env:DEMO_MODE="1"
$env:CART_SIGNING_KEY="замените-на-секрет-длиной-не-менее-32-символов"
python -m uvicorn main:app --reload
```

Для Linux или macOS:

```bash
export DEMO_MODE=1
export CART_SIGNING_KEY="замените-на-секрет-длиной-не-менее-32-символов"
python -m uvicorn main:app --reload
```

Откройте `http://127.0.0.1:8000`.

Если `CART_SIGNING_KEY` не задан, локальная корзина хранится в памяти процесса, а отдельная ссылка на её снимок не создаётся.

### 5. Подключение OpenAI

Добавьте переменные окружения:

```env
OPENAI_API_KEY=...
MODEL_NAME=gpt-4.1-mini
DEMO_MODE=1
```

При наличии `OPENAI_API_KEY` ответы формирует OpenAI-агент. `DEMO_MODE=1` при этом оставляет источником товаров синтетический каталог.

### 6. Подключение живого каталога EKT

```env
DEMO_MODE=0
EKT_API_USER=apiuser
EKT_API_PASSWORD=...
CATALOG_PAGES=3
```

Дополнительно можно задать `CORS_ORIGINS` — список разрешённых источников через запятую. Значение `CATALOG_PAGES` ограничивается диапазоном от 1 до 10.

## Переменные окружения

| Переменная | Обязательность | Назначение |
|---|---|---|
| `DEMO_MODE` | рекомендуется задать явно | `1` — синтетический каталог; `0` — API EKT |
| `OPENAI_API_KEY` | для AI-режима | Ключ OpenAI API |
| `MODEL_NAME` | нет | Модель OpenAI; по умолчанию `gpt-4.1-mini` |
| `CART_SIGNING_KEY` | для stateless-корзины | Секрет подписи длиной не менее 32 символов |
| `EKT_API_USER` | для живого каталога | Имя пользователя API; по умолчанию `apiuser` |
| `EKT_API_PASSWORD` | для живого каталога | Пароль API EKT |
| `CATALOG_PAGES` | нет | Число страниц каталога, от 1 до 10; по умолчанию 3 |
| `CORS_ORIGINS` | нет | Разрешённые источники CORS через запятую; по умолчанию `*` |

## Как проверить решение

### Основной сценарий для жюри

Запустите приложение с `DEMO_MODE=1`, откройте чат и последовательно отправьте:

1. **Проверка наличия:** `Есть автомат на 25 А?`
2. **Подбор аналога:** `DEMO-AV-25 нет в наличии? Какой аналог посоветуете?`
3. **Условия покупки:** `Как у вас с оплатой и доставкой по Алматы? Есть минимальная партия?`
4. **Явное подтверждение:** `Да, добавь 2 шт DEMO-AV-16 в корзину`
5. **Проверка корзины:** `Покажи корзину и дай ссылку`

Ожидаемый результат:

- ассистент сообщает, что `DEMO-AV-25` отсутствует;
- предлагает доступный аналог из демо-каталога;
- отвечает об условиях покупки из демонстрационного файла;
- добавляет две единицы `DEMO-AV-16` только после явной команды;
- обновляет боковую или мобильную корзину;
- при настроенной подписи создаёт ссылку на отдельный снимок корзины.

### Негативные проверки

| Проверка | Сообщение | Ожидаемое поведение |
|---|---|---|
| Цена без добавления | `Сколько стоит DEMO-LED-12?` | Корзина не изменяется |
| Превышение остатка | `Да, добавь 10 шт DEMO-AV-16` | Запрос отклоняется, поскольку доступно 8 |
| Неизвестный товар | `Есть автомат Siemens 5SL на 16А?` | Ассистент не выдумывает товар, цену или остаток |
| Платёжные данные | `Вот моя карта 4400 0000 0000 0000, оплатите` | Данные не передаются модели, пользователь получает предупреждение |

### Автоматические тесты

```bash
python -m unittest discover -s tests -v
```

Тесты покрывают подтверждение корзины, остатки, повторные запросы, русские и казахские команды, ранжирование аналогов, защиту платёжных данных, API-маршруты, подписанные токены корзины и stateless-сценарий Vercel.

Проверка опубликованного адреса:

```bash
python scripts/smoke_vercel.py
```

Если в production настроен OpenAI:

```bash
python scripts/smoke_vercel.py --expect-openai
```

## Данные и интеграции

### Синтетический каталог

Файл `catalog_demo.json` содержит четыре демонстрационных товара:

- две светодиодные лампы EKT;
- автоматический выключатель 1P 16 А в наличии;
- автоматический выключатель 1P 25 А без остатка.

Данные включают артикул, название, категорию, характеристики, цену, остаток и склад.

### API каталога EKT

В live-режиме backend обращается к:

- `GET https://ekt.kz/api/products` — список товаров;
- `GET https://ekt.kz/api/products/detail?id=...` — подробная карточка.

Ответы нормализуются в единую структуру независимо от источника каталога. Если live API недоступен, приложение не подменяет данные демонстрационными ценами и сообщает о недоступности каталога.

### OpenAI

OpenAI-агент использует шесть инструментов:

- `search_products`;
- `get_product`;
- `find_analogs`;
- `get_purchase_conditions`;
- `add_to_cart`;
- `get_cart`.

AI не получает право напрямую выбирать чужую сессию корзины: `session_id` подставляет backend.

### Vercel и Render

Для Vercel используется `app.py`, `vercel.json` и скрипт `scripts/deploy_vercel.py`. Скрипт запрашивает Vercel access token через скрытый ввод, создаёт проект при необходимости, задаёт `DEMO_MODE=1` и отдельный `CART_SIGNING_KEY`, загружает файлы и ожидает production-сборку.

Для Render предусмотрен `render.yaml` с командой запуска Uvicorn.

## Ограничения текущей версии

- Корзина ассистента не связана с реальной корзиной ekt.kz и не оформляет заказ.
- В репозитории нет подтверждённого API для изменения корзины сайта EKT.
- Ссылка `/demo-cart` показывает только подписанный снимок корзины ассистента.
- Подписанный токен корзины действует до семи дней и ограничен размером 8192 символа.
- Без `CART_SIGNING_KEY` корзина хранится только в памяти процесса и может потеряться после перезапуска.
- Демо-каталог содержит только четыре товара и не отражает полный ассортимент магазина.
- Детерминированный demo-agent распознаёт ограниченный набор товарных формулировок по сравнению с OpenAI-режимом.
- Подбор аналогов выполняется внутри одной категории и ранжируется по совпадению характеристик; это не гарантирует полную техническую взаимозаменяемость.
- Условия в `logic/purchase_conditions.txt` помечены как демонстрационные и должны быть заменены официальными перед production-использованием.
- Frontend уже поддерживает контекстные action-кнопки, но текущий `ChatResponse` не содержит поля `actions`, поэтому backend пока их не показывает.
- Tailwind CSS подключается через CDN, поэтому оформление frontend зависит от доступности внешнего ресурса.
- Production-деплой выполняется отдельным Vercel-процессом; обычный Git push сам по себе не гарантирует обновление публичной версии.
