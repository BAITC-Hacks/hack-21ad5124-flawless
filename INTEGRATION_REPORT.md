# Отчёт по интеграции прототипа

Дата проверки: 23.09.2026.

## Что объединено

- `backend` (`349ab32`) — FastAPI, каталог, агент и корзина;
- `feature/logic` (`677c9a9`, включая PR #1) — системный промпт, правила покупки и демо-сценарий;
- `Yernurwork` (`ef26edb`) — актуальный адаптивный интерфейс с отдельной панелью корзины;
- результат подготовлен в `integration/prototype`, без записи в `main`.

## Решения конфликтов

- Сервер, каталог и корзина: сохранена версия владельца backend с дополнительным hardening.
- Промпт и условия: `logic/system_prompt.txt` и `logic/purchase_conditions.txt` — единственные источники правды в обоих режимах.
- Интерфейс: сохранён последний дизайн фронтенда, включая мобильный drawer корзины.
- `README.md`: объединены запуск, публичная ссылка, прямой API EKT и ограничения корзины.
- Контракт не расширен: `POST /api/chat` принимает только `{session_id, messages[]}` и возвращает только `{reply, cart, cart_link}`. Vercel-специфичные `cart_token` и `assistant_source` из фронтовой ветки исключены.
- `cart_link` снова равен `https://ekt.kz/cart`, как зафиксировано в `logic/TEAM_PLAN.md`.
- Pinecone не добавлялся: живой каталог читается напрямую из API EKT; демо-режим содержит 40 синтетических позиций.

## Выполненные проверки

- `python -m unittest discover -s tests -q`: 109 тестов прошли.
- `node --check static/app.js`: синтаксис корректен.
- Локальный uvicorn smoke: `/health` вернул `demo`, 40 товаров; контракт ответа точный.
- Пять шагов главного сценария пройдены через настоящий HTTP: аналог найден, 2 штуки добавлены, корзина сохранилась, ссылка EKT возвращена.
- Off-script запросы ВВГ 3х2.5, ABB 40 А и светильник 36 Вт проходят через полный демо-agent path.
- Автотесты покрывают запрет добавления без согласия, остаток, дробные/нулевые/отрицательные/огромные количества, 15 разговорных форм согласия, повторные и конкурентные запросы, подмену товара, джейлбрейк, выдуманные SKU/цены, платёжные данные, казахский язык, пустой и длинный ввод.

## Снимок опубликованного демо

`https://ekt-ai-assistant-demo.vercel.app` доступен без авторизации. На момент проверки `/health` сообщал `catalog_source=demo`, `products=4`, а запрос обслуживался OpenAI. Это старая сборка, не текущая интеграционная ветка.

На старой публикации прошли: неизвестный SKU, отказ раскрыть промпт/дать скидку 90%, отрицательное и дробное количество, превышение остатка, казахский запрос и лимит 8000 символов. Не прошли: ВВГ вне четырёх товаров, пробельное сообщение и пять разговорных подтверждений. Эти случаи закрыты в интеграционной ветке тестами и кодом, но должны быть повторно проверены уже после нового деплоя с настоящим OpenAI.

## Известные ограничения и обязательные действия перед защитой

1. Перезадеплоить именно `integration/prototype`; текущий публичный URL всё ещё показывает старые 4 товара.
2. Для живого режима задать защищённые `OPENAI_API_KEY`, `EKT_API_USER`, `EKT_API_PASSWORD`, `DEMO_MODE=0`. Секреты в Git не добавлять.
3. Повторить один credentialed smoke нового параллельного загрузчика на реальном EKT API. Его полнота, порядок, retry и fail-closed проверены офлайн; до оптимизации API возвращал около 15 тысяч позиций.
4. Условия в `logic/purchase_conditions.txt` помечены как демонстрационные. До продакшена нужны официальные условия EKT.
5. Выданный API EKT не содержит метода изменения реальной корзины. Панель ассистента хранится в памяти и не синхронизируется с сайтом.
6. После деплоя вручную проверить Chrome desktop и мобильный Chrome/Safari: главный сценарий, drawer корзины и отсутствие горизонтального скролла.

## Команды запуска

```bash
pip install -r requirements.txt
export DEMO_MODE=1
uvicorn main:app --host 0.0.0.0 --port 8000
```

Для PowerShell:

```powershell
$env:DEMO_MODE = "1"
uvicorn main:app --host 0.0.0.0 --port 8000
```
